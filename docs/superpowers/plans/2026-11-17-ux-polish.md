# UX polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring every widget the final review rated "good" to world class, and fix what the real-shape demo data exposed: item grids that fill their card with one-line names, charts that show what decides a status, phone layouts for the Report and Customize mode, and published reports that count every metric as the Overview did.

**Architecture:** Five tasks with single-owner files, run in two waves. Wave 1 (parallel): Task 1 (item grid and names), Task 3 (charts), Task 5 (published report standings, Report on phones, phone shell). Wave 2 (parallel, after Tasks 1 and 3): Task 2 (drill-in) and Task 4 (Overview widgets). One API change (Task 5): an optional `standing` view in published report documents.

**Tech Stack:** React 19, TypeScript, Tailwind 4, Radix (Dialog, DropdownMenu, Tooltip), Recharts 3, lucide-react, Vitest + Testing Library + vitest-axe; Go API (oapi-codegen), `make gen`.

**Spec:** `docs/superpowers/specs/2026-11-17-ux-polish-design.md` (extends `docs/superpowers/specs/2026-11-16-dashboard-ux-design.md`). Mockups (local, not committed): `.superpowers/sdd/2026-11-17-ux-polish/mockups/`. Audit: `.superpowers/sdd/2026-11-17-ux-polish/audit/audit.md`.

## Global Constraints

- No new dependencies (web or Go). No horizontal scroll at 320–1920px (`document.documentElement.scrollWidth === clientWidth`); a dialog body may scroll vertically; no nested scroll areas.
- Type scale: 11/16, 12/16, 14/20, 16/24, 20/28, 28/36 only. All text `ink/70` or stronger; `ink/55` for non-text only. Targets ≥ 24px (icon buttons 32px).
- Status is never color alone: chips carry shape and letter, cells carry the letter.
- Copy is exact as in the spec; sentence case; the tenant's scale labels (`Red`), never rank labels.
- Public repo: no company or product names in code, tests, docs or commit messages; demo names only.
- Do not edit a file another task owns. Wave 2 tasks may import from Wave 1 files, not change them.
- Dev servers: `make dev`, or when ports 8080/5173 are taken, `api: go run ./cmd/devserver -addr 127.0.0.1:8098 -allowed-origin http://localhost:5198 -seed demo -auth dev -dev-secret opsvision-local-dev-secret-not-for-production` and `web: VITE_API_URL=http://127.0.0.1:8098 VITE_AUTH_MODE=dev npx vite --port 5198 --strictPort`. Stop only the processes you started.
- Every task ends with: `npm --prefix web test` (state the file and test counts; the baseline at `f48840e` is 91 files, 1454 tests), `npm --prefix web run typecheck`, `npm --prefix web run lint` (0 errors), `cd api && go test ./...` when the task touches `api/`, and screenshots at 1440, 1024, 390 and 360 of what it touched against the dev servers, saved to `.superpowers/sdd/2026-11-17-ux-polish/task-N/`.

## Review Focus

1. **Item names with no separator, or a separator at the very start or end** (`Edge Cache`, `- Primary`, `Search /`): `splitItemName` must return a usable head/tail and `ItemName` must render the whole name on one line. Tested in Task 1.
2. **A filter that matches only collapsed (no-reports) items**: the rows appear, the Show button hides, the count reads `2 match`, and arrow keys reach them. Tested in Task 1.
3. **Stepping past the ends, or the item disappearing from the order** (filter changed, sort changed while drilled in): the stepper disables at the ends; an item not in the order shows `–` as its position and both buttons step into the order from its nearest neighbour by name. Tested in Task 2.
4. **A v1 published report with no coarse metrics**, and a v2 report read by a contributor scoped to one segment: no "not counted" line for the first; `standing` filtered like `view` for the second. Tested in Task 5.
5. **Money plan with every month under plan, and with a single month in view**: the domain mirrors (under side large, over side small), and one bar still draws with its label. Tested in Task 3.
