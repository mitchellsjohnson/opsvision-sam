# UX polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring every widget the final review rated "good" to world class, and fix what the real-shape demo data exposed: item grids that fill their card with one-line names, charts that show what decides a status, phone layouts for the Report and Customize mode, and published reports that count every metric as the Overview did.

**Architecture:** Seven tasks with single-owner files, in two waves. Wave 1 (parallel): T1 item grid and names, T3 charts, T5a standing API and report model, T6 phone shell. Wave 2 (parallel, after every Wave 1 commit): T2 drill-in, T4 Overview widgets, T5b Report on phones. One API change (T5a): an opt-in `standing` view in published report documents.

**Tech Stack:** React 19, TypeScript, Tailwind 4, Radix (Dialog, DropdownMenu, Tooltip), Recharts 3, lucide-react, Vitest + Testing Library + vitest-axe; Go API (oapi-codegen, kin-openapi), `make gen`.

**Spec:** `docs/superpowers/specs/2026-11-17-ux-polish-design.md` (extends `docs/superpowers/specs/2026-11-16-dashboard-ux-design.md`). Mockups (local, not committed): `.superpowers/sdd/2026-11-17-ux-polish/mockups/`. Audit: `.superpowers/sdd/2026-11-17-ux-polish/audit/audit.md`. Design review: `.superpowers/sdd/2026-11-17-ux-polish/spec-review.md`.

## Global Constraints

- No new dependencies (web or Go). No horizontal scroll at 320–1920px (`document.documentElement.scrollWidth === clientWidth`); a dialog body may scroll vertically; no nested scroll areas.
- Type scale: 11/16, 12/16, 14/20, 16/24, 20/28, 28/36 only. All text `ink/70` or stronger; `ink/55` for non-text only. Targets ≥ 24px (icon buttons 32px). Status is never color alone.
- Copy is exact as in the spec; sentence case; the tenant's scale labels (`Red`), never rank labels.
- Public repo: no company or product names in code, tests, docs or commit messages; demo names only.
- **One checkout, parallel tasks.** Tasks in a wave run at the same time in this checkout (no branches, no worktrees). Each task:
  1. Edits only the files its **Files** list owns. Wave 2 tasks import Wave 1 code; they never edit it.
  2. Runs its own dev servers on its own ports, and stops only the processes it started (never `pkill`):

     | Task | API | Web |
     |---|---|---|
     | T1 | 8091 | 5191 |
     | T2 | 8092 | 5192 |
     | T3 | 8093 | 5193 |
     | T4 | 8094 | 5194 |
     | T5a | 8095 | 5195 |
     | T6 | 8096 | 5196 |
     | T5b | 8097 | 5197 |

     ```bash
     (cd api && go run ./cmd/devserver -addr 127.0.0.1:$API -allowed-origin http://localhost:$WEB -seed demo -auth dev -dev-secret opsvision-local-dev-secret-not-for-production)
     (cd web && VITE_API_URL=http://127.0.0.1:$API VITE_AUTH_MODE=dev npx vite --port $WEB --strictPort)
     ```
  3. While working, may run targeted tests in the shared tree (other tasks' half-finished edits can make unrelated tests fail there; ignore those and never fix another task's file).
  4. Runs its **final gate in a temporary export of `HEAD` with only its own changed files copied in**, so the counts are its own:

     ```bash
     FILES="<this task's created and modified files>"        # and DELETED="<removed files>", if any
     EX=$(mktemp -d "/tmp/opsv-gate-$TASK.XXXX")
     git archive HEAD | tar -x -C "$EX"
     for f in $FILES; do mkdir -p "$EX/$(dirname "$f")"; cp "$f" "$EX/$f"; done
     for f in $DELETED; do rm -f "$EX/$f"; done
     ln -s "$PWD/web/node_modules" "$EX/web/node_modules"
     (cd "$EX/web" && npx vitest run && npx tsc -b --noEmit && npx eslint .)   # state files and tests counted
     (cd "$EX/api" && go test ./...)                                           # when the task touches api/
     (cd "$EX" && make gen-check)                                              # T5a only
     rm -rf "$EX"
     ```
  5. Commits only its own files: `git add -- $FILES && git commit --only -m "<message>" -- $FILES` (`--only` commits exactly those paths, whatever else is staged). If `.git/index.lock` exists, wait and retry; never delete it.
- Every gate: the full web suite with file and test counts (baseline at `f48840e`: 91 files, 1454 tests), typecheck, lint with 0 errors, `go test ./...` when the task touches `api/`, and screenshots at 1440, 1024, 390 and 360 of what it touched against its own dev servers, saved to `.superpowers/sdd/2026-11-17-ux-polish/task-<id>/`, with `scrollWidth === clientWidth` noted. Wave 1 phone screenshots (except T6's) are taken with the icon rail still present; the final pass re-shoots phones after T6.

## Review Focus

1. **Item names with no separator, or a separator at the very start or end** (`Edge Cache`, `- Primary`, `Search /`, `Payments Gateway (EU Primary)`): one line, the last two words kept for three or more words. Tested in T1.
2. **A filter that matches only silent items**: rows appear under `… · 2 match`, the Show button hides, the tab stop is the first match and ArrowDown reaches the second. Tested in T1.
3. **The drilled item not in the order** (opened by link with its group collapsed, or filtered out) **and stepping at the ends**: position `–`, Previous disabled, Next to the first item; no wrap-around at either end. Tested in T2.
4. **A v1 published report with no coarse metrics, and a v2 report read by a contributor scoped to one segment**: no "not counted" line for the first; `standing` filtered like `view` for the second. Tested in T5a.
5. **Money plan with every month under plan, and with one month in view**: the domain mirrors (under side large, over side small), and one bar still draws with its label. Tested in T3.
